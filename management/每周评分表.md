# 每周评分标准与记录表

## 通用评分（适用于 W03～W14；W02 有具体模块分）

| 项目 | 满分 | 0 分 / 较低分的典型情形 | 满分参考 |
|---|---:|---|---|
| 功能正确性与完成度 | 40 | 无运行证据，核心任务不工作 | 可复现、核心边界情况处理正常 |
| 原理理解与解释 | 25 | 只能重复教程文字，解释不了数据流 | 可以解释关键变量和修改理由 |
| 自主排错与反馈 | 20 | 无尝试记录，遇错直接弃置 | 能写最小复现、查日志、提出假设 |
| 工程规范与提交 | 15 | 无 README、无构建方式、文件散乱 | 清晰 README、Git 历史、测试记录 |
| **总计** | **100** | | |

## 主力评分建议

- 只看成果不等于只看分数；可要求 1～2 道随机问题或现场轻微改动。
- 对 W02 使用 [W02 单独评分表](../weeks/week02/任务.md)；记录到表格时可统一折算为 100 分。
- 不机械规定“某分数必然淘汰”；与持续参与、主动反馈共同判断。

## 建议记录字段（可拷入任意在线表格）

```csv
week,github_id,submitted_on_time,function_40,understanding_25,debug_20,docs_15,total,attitude,blocker,feedback,makeup_deadline
W02,example,false,0,0,0,0,0,unknown,,, 
```

注意不要把健康、家庭等隐私原因写到公开评分表中；仅记录是否主动说明、是否批准延期。
