# W01 每周任务：入队环境与规则（已布置，补充复盘）

- **日期**：2026-11-09 ～ 2026-11-15
- **截止**：2026-11-15（周日）23:59，中国标准时间 UTC+8
- **投入预算**：7 小时/人；环境检查 2h／规则阅读 3h／复盘 2h
- **完成形式**：四人各自独立完成；允许查文档和使用 AI，但必须能解释自己的代码。
- **先读**：[知识.md](知识.md)；W02 另有专题知识文档。

## 本周要达成什么能力？

验证 Ubuntu 安装与 RoboMaster 自瞄基本任务认知，不以复杂代码为目标。

## 完成路径（按顺序做）

1. 检查 `lsb_release -a`、`g++ --version`、`git --version`，写下异常及解决过程。
2. 从队内指定的 2027 赛季规则手册抽取与装甲板、自瞄有关的条目，逐项注明章节与页码。
3. 画一张自瞄链路流程图，用自己的话说明每一阶段输入与输出。

## 基础必做（以可复现为准）

- [ ] 环境清单及操作截图
- [ ] 一页规则摘要（标明规则版本/页码）
- [ ] 一张自瞄数据流图

## 选做挑战（不作为留队硬门槛）

- 找出一个规则变化可能影响旧版检测器的原因

## 交付方式与证据

1. 在本人分支或个人提交目录中上传源码、CMakeLists、README 与测试记录；不要上传 `build/`、系统文件、未授权比赛视频、设备密钥。
2. 至少记录一次“错误现象 → 排查动作 → 最终结论”；即使未解决，也记录已验证的事实。
3. 提交一个 PR（初期不会 PR 可以先提交个人分支并报告链接），标题格式：`W01 学员昵称 - 任务主题`。
4. PR 描述复制 [提交模板](../../templates/SUBMISSION_TEMPLATE.md)，不得只上传截图而没有源码。

## 验收清单（主力抽查）

- [ ] 分辨检测与定位
- [ ] 指出规则来源和版本
- [ ] 能描述 2027 赛季规则不确定项

### 口头/录屏追问（任选 1～2 题）

1. “识别装甲板”和“解算装甲板距离”为什么不是一个问题？
2. 如果规则更新了装甲板外观，项目中哪些模块可能要改？

## 如果做不出来怎么办？

- 先完成能工作的最小版本，不要为了选做任务耗光 7 小时。
- 超过 30 分钟仍卡住，按 [求助模板](../../templates/HELP_TEMPLATE.md) 记录现象、尝试和日志，发 GitHub Issue / 群里求助。
- 截止前主动说明卡点可申请一次补交；**未完成但有真实排错记录**，与无说明不提交区别评价。
- 本周属于培训计划，不需要实车联调或新模型训练。
