# W04 每周任务：OpenCV 读图/读视频与最小可运行工程

- **日期**：2026-11-30 ～ 2026-12-06
- **截止**：2026-12-06（周日）23:59，中国标准时间 UTC+8
- **投入预算**：7 小时/人；学习 2h／编码 3h／测试 1h／提交 1h
- **完成形式**：四人各自独立完成；允许查文档和使用 AI，但必须能解释自己的代码。
- **先读**：[知识.md](知识.md)；W02 另有专题知识文档。

## 本周要达成什么能力？

从装甲板视频读取帧并正常显示、暂停、输出信息。

## 完成路径（按顺序做）

1. 安装 OpenCV 开发库与 pkg-config（Ubuntu 可使用 apt；版本以本机为准）。
2. 编写程序从命令行接收视频路径，打开并显示视频。
3. 在图像左上角叠加当前帧序号、宽高与实际处理耗时。
4. 按 `q` 退出，文件不存在时给出清晰错误信息。

## 基础必做（以可复现为准）

- [ ] 可运行程序 + CMake
- [ ] 支持命令行路径参数
- [ ] 至少一个静止和一个旋转视频运行记录
- [ ] README 中说明图像通道与像素坐标

## 选做挑战（不作为留队硬门槛）

- 封装 `VideoReader` 类或实现暂停/继续

## 交付方式与证据

1. 在本人分支或个人提交目录中上传源码、CMakeLists、README 与测试记录；不要上传 `build/`、系统文件、未授权比赛视频、设备密钥。
2. 至少记录一次“错误现象 → 排查动作 → 最终结论”；即使未解决，也记录已验证的事实。
3. 提交一个 PR（初期不会 PR 可以先提交个人分支并报告链接），标题格式：`W04 学员昵称 - 任务主题`。
4. PR 描述复制 [提交模板](../../templates/SUBMISSION_TEMPLATE.md)，不得只上传截图而没有源码。

## 验收清单（主力抽查）

- [ ] 可正确处理视频结束
- [ ] 显示至少 2 类输入
- [ ] 解释视频 FPS 和算法 FPS

### 口头/录屏追问（任选 1～2 题）

1. 为什么不应该在失败时继续访问空 Mat？
2. 为什么一段视频的播放速度可能和处理速度不同？

## 如果做不出来怎么办？

- 先完成能工作的最小版本，不要为了选做任务耗光 7 小时。
- 超过 30 分钟仍卡住，按 [求助模板](../../templates/HELP_TEMPLATE.md) 记录现象、尝试和日志，发 GitHub Issue / 群里求助。
- 截止前主动说明卡点可申请一次补交；**未完成但有真实排错记录**，与无说明不提交区别评价。
- 本周属于培训计划，不需要实车联调或新模型训练。
