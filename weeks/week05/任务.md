# W05 每周任务：OpenCV 图像处理与灯条候选

- **日期**：2026-12-07 ～ 2026-12-13
- **截止**：2026-12-13（周日）23:59，中国标准时间 UTC+8
- **投入预算**：7 小时/人；学习 2h／开发 3h／测试/提交 2h
- **完成形式**：四人各自独立完成；允许查文档和使用 AI，但必须能解释自己的代码。
- **先读**：[知识.md](知识.md)；W02 另有专题知识文档。

## 本周要达成什么能力？

实现可观察、可调参的传统检测预处理，而非一口气写出成熟装甲板检测器。

## 完成路径（按顺序做）

1. 读取 W4 视频，在 BGR/HSV（任选其一，解释理由）空间产生二值图。
2. 实现阈值参数可调、形态学处理并显示中间结果。
3. 用轮廓面积或长宽比过滤明显噪声，画出候选框。
4. 记录对光照变化、旋转视频的失败案例。

## 基础必做（以可复现为准）

- [ ] 原图、二值图、候选框三类可视化
- [ ] 至少两段视频运行效果
- [ ] 写出至少 2 种误检/漏检情况及原因

## 选做挑战（不作为留队硬门槛）

- 基于两个候选灯条组合为装甲板候选
- 对视频抽帧保存用于后期小型数据集

## 交付方式与证据

1. 在本人分支或个人提交目录中上传源码、CMakeLists、README 与测试记录；不要上传 `build/`、系统文件、未授权比赛视频、设备密钥。
2. 至少记录一次“错误现象 → 排查动作 → 最终结论”；即使未解决，也记录已验证的事实。
3. 提交一个 PR（初期不会 PR 可以先提交个人分支并报告链接），标题格式：`W05 学员昵称 - 任务主题`。
4. PR 描述复制 [提交模板](../../templates/SUBMISSION_TEMPLATE.md)，不得只上传截图而没有源码。

## 验收清单（主力抽查）

- [ ] 解释阈值调节为何影响召回
- [ ] 能正确标注失败情况
- [ ] 代码结构不依赖绝对路径

- 截止前主动说明卡点可申请一次补交；**未完成但有真实排错记录**，与无说明不提交区别评价。
- 本周属于培训计划，不需要实车联调或新模型训练。
