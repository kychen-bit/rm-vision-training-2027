# W03 知识文档：C++ 编程习惯 + Git + CMake

> 对象：四名大一自瞄新人｜每周约 7 小时｜**先理解用途，再跟着示例实践，最后独立完成任务**。

## 本周到底在做什么？

从“复制单文件能运行”进步到“独立维护可编译的小型工程”。

## 为什么要学？它在 RoboMaster 自瞄中有什么用？

RM 自瞄是多人维护的工程，头文件、源码、构建脚本、版本记录和错误定位比一次性运行更重要。

## 你需要建立的基础认识

1. 函数职责单一：输入、处理、输出分开，错误需要有可见反馈。
2. 头文件声明接口、源文件实现；不要把所有功能塞进 main.cpp。
3. CMake 描述编译目标，`cmake -S . -B build` 配置，`cmake --build build` 构建。
4. Git 的 commit 是历史快照，branch 隔离自己的改动，PR 用来评审。

## 推荐学习顺序（不要求死记全部 API）

1. 把 W2 的二维变换程序重构为 `include/transform.hpp`、`src/transform.cpp`、`src/main.cpp`。
2. 加入输入检查：非数字、角度越界（可自行定义合理范围）时提示错误。
3. 编写 CMakeLists，写下从零编译的命令；本周开始每人按独立分支提交 PR。
4. README 记录程序用途、使用方法、测试表和一次排错经历。

## 常见错误与提醒

- 只复制教程里的命令/代码而不记录“输入是什么、输出是什么、为什么成功”，不能算真正掌握。
- 任何相机尺寸、角点次序、坐标系、规则版本等关键假设，必须写明来源或标注“教学假设”。
- 遇到和文档不同的环境、版本或数据，不要硬套结果；先保存日志和最小复现步骤。
