# W03 每周任务：C++ 编程习惯 + Git + CMake

- **日期**：2026-11-23 ～ 2026-11-29
- **截止**：2026-11-29（周日）23:59，中国标准时间 UTC+8
- **投入预算**：7 小时/人；C++ 3h／Git 1.5h／CMake 1.5h／提交 1h
- **完成形式**：四人各自独立完成；允许查文档和使用 AI，但必须能解释自己的代码。
- **先读**：[知识.md](知识.md)；W02 另有专题知识文档。

## 本周要达成什么能力？

从“复制单文件能运行”进步到“独立维护可编译的小型工程”。

## 完成路径（按顺序做）

1. 把 W2 的二维变换程序重构为 `include/transform.hpp`、`src/transform.cpp`、`src/main.cpp`。
2. 加入输入检查：非数字、角度越界（可自行定义合理范围）时提示错误。
3. 编写 CMakeLists，写下从零编译的命令；本周开始每人按独立分支提交 PR。
4. README 记录程序用途、使用方法、测试表和一次排错经历。

## 基础必做（以可复现为准）

- [ ] 至少 1 个头文件 + 2 个源文件
- [ ] 可复现的 CMake 构建
- [ ] 不少于 3 次有意义的 Git commit
- [ ] README 和 PR

## 选做挑战（不作为留队硬门槛）

- 使用 `ctest` 添加自动测试

## 交付方式与证据

1. 在本人分支或个人提交目录中上传源码、CMakeLists、README 与测试记录；不要上传 `build/`、系统文件、未授权比赛视频、设备密钥。
2. 至少记录一次“错误现象 → 排查动作 → 最终结论”；即使未解决，也记录已验证的事实。
3. 提交一个 PR（初期不会 PR 可以先提交个人分支并报告链接），标题格式：`W03 学员昵称 - 任务主题`。
4. PR 描述复制 [提交模板](../../templates/SUBMISSION_TEMPLATE.md)，不得只上传截图而没有源码。

## 验收清单（主力抽查）

- [ ] 能从全新 build 目录编译
- [ ] 解释 include 与链接的区别
- [ ] 能通过 git log 找到个人工作

### 口头/录屏追问（任选 1～2 题）

1. 为什么不把 build 文件夹提交仓库？
2. 同学修改了你的代码，怎样知道具体改了哪里？

## 如果做不出来怎么办？

- 先完成能工作的最小版本，不要为了选做任务耗光 7 小时。
- 超过 30 分钟仍卡住，按 [求助模板](../../templates/HELP_TEMPLATE.md) 记录现象、尝试和日志，发 GitHub Issue / 群里求助。
- 截止前主动说明卡点可申请一次补交；**未完成但有真实排错记录**，与无说明不提交区别评价。
- 本周属于培训计划，不需要实车联调或新模型训练。
