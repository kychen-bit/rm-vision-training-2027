# W10 每周任务：综合项目验收与阶段筛选

- **日期**：2027-01-11 ～ 2027-01-17
- **截止**：2027-01-17（周日）23:59，中国标准时间 UTC+8
- **投入预算**：7 小时/人；测试整理 3h／报告 2h／录屏及答辩 2h
- **完成形式**：四人各自独立完成；允许查文档和使用 AI，但必须能解释自己的代码。
- **先读**：[知识.md](知识.md)；W02 另有专题知识文档。

## 本周要达成什么能力？

证明能够独立复现 MiniAutoAim、解释链路、排查一个小故障。

## 完成路径（按顺序做）

1. 冻结可运行版本，整理构建与运行步骤。
2. 以静止、旋转、缺目标三种场景演示。
3. 随机抽一帧，解释从输入到解算输出每一步。
4. 回答一项临时更改（例如改变无目标输出文字、变更日志字段、修改输入错误提示）。

## 基础必做（以可复现为准）

- [ ] 可复现代码、说明文档、测试日志
- [ ] 不超过 5 分钟的演示
- [ ] 1～2 页项目复盘
- [ ] 现场/录屏答辩

## 选做挑战（不作为留队硬门槛）

- 补充角点噪声敏感性实验
- 增加自动检测候选

## 交付方式与证据

1. 在本人分支或个人提交目录中上传源码、CMakeLists、README 与测试记录；不要上传 `build/`、系统文件、未授权比赛视频、设备密钥。
2. 至少记录一次“错误现象 → 排查动作 → 最终结论”；即使未解决，也记录已验证的事实。
3. 提交一个 PR（初期不会 PR 可以先提交个人分支并报告链接），标题格式：`W10 学员昵称 - 任务主题`。
4. PR 描述复制 [提交模板](../../templates/SUBMISSION_TEMPLATE.md)，不得只上传截图而没有源码。

## 验收清单（主力抽查）

- [ ] 可编译并成功处理 2 段视频
- [ ] 失败情况有说明
- [ ] 对随机提问能定位到代码位置

### 口头/录屏追问（任选 1～2 题）

1. 你的项目还不能承担实车自瞄的哪几项职责？
2. 现有输出在哪些条件下可能不可信？

## 如果做不出来怎么办？

- 先完成能工作的最小版本，不要为了选做任务耗光 7 小时。
- 超过 30 分钟仍卡住，按 [求助模板](../../templates/HELP_TEMPLATE.md) 记录现象、尝试和日志，发 GitHub Issue / 群里求助。
- 截止前主动说明卡点可申请一次补交；**未完成但有真实排错记录**，与无说明不提交区别评价。
- 本周属于培训计划，不需要实车联调或新模型训练。
