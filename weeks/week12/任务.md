# W12 每周任务：运行队内工程：编译、离线输入、观察日志

- **日期**：2027-01-25 ～ 2027-01-31
- **截止**：2027-01-31（周日）23:59，中国标准时间 UTC+8
- **投入预算**：7 小时/人；环境 2h／运行 2h／定位 2h／提交 1h
- **完成形式**：四人各自独立完成；允许查文档和使用 AI，但必须能解释自己的代码。
- **先读**：[知识.md](知识.md)；W02 另有专题知识文档。

## 本周要达成什么能力？

安全运行队内工程可离线部分，并写出完整复现步骤。

## 完成路径（按顺序做）

1. 由主力提供一个固定版本、运行前置条件和允许操作范围。
2. 从干净 shell 编译或运行队内离线演示，记录遇到的错误及处理。
3. 使用 ros2 topic/日志观察模块输出（仅访问允许的测试环境）。
4. 给出“新电脑复现清单”，列出无法复现的条件。

## 基础必做（以可复现为准）

- [ ] 实际环境、版本、命令清单
- [ ] 至少一条运行成功或卡点可复现证据
- [ ] 一份日志问题分析
- [ ] 不得直接修改比赛核心分支

## 选做挑战（不作为留队硬门槛）

- 提供一个无实车输入的回放脚本

## 交付方式与证据

1. 在本人分支或个人提交目录中上传源码、CMakeLists、README 与测试记录；不要上传 `build/`、系统文件、未授权比赛视频、设备密钥。
2. 至少记录一次“错误现象 → 排查动作 → 最终结论”；即使未解决，也记录已验证的事实。
3. 提交一个 PR（初期不会 PR 可以先提交个人分支并报告链接），标题格式：`W12 学员昵称 - 任务主题`。
4. PR 描述复制 [提交模板](../../templates/SUBMISSION_TEMPLATE.md)，不得只上传截图而没有源码。

## 验收清单（主力抽查）

- [ ] 清楚哪些节点是实车依赖
- [ ] 能解释一项编译错误原因
- [ ] 遇到问题不删除未理解的关键配置

### 口头/录屏追问（任选 1～2 题）

1. 为什么 source 错的环境会造成依赖冲突？
2. 能编译成功但没有输出，应从哪里排查？

## 如果做不出来怎么办？

- 先完成能工作的最小版本，不要为了选做任务耗光 7 小时。
- 超过 30 分钟仍卡住，按 [求助模板](../../templates/HELP_TEMPLATE.md) 记录现象、尝试和日志，发 GitHub Issue / 群里求助。
- 截止前主动说明卡点可申请一次补交；**未完成但有真实排错记录**，与无说明不提交区别评价。
- 本周属于培训计划，不需要实车联调或新模型训练。
