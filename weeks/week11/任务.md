# W11 每周任务：理解 ROS2 自瞄项目的数据流

- **日期**：2027-01-18 ～ 2027-01-24
- **截止**：2027-01-24（周日）23:59，中国标准时间 UTC+8
- **投入预算**：7 小时/人；阅读 3h／画图 2h／验证 1h／提交 1h
- **完成形式**：四人各自独立完成；允许查文档和使用 AI，但必须能解释自己的代码。
- **先读**：[知识.md](知识.md)；W02 另有专题知识文档。

## 本周要达成什么能力？

读懂现有工程的模块职责和消息传递，不要求新人重写节点。

## 完成路径（按顺序做）

1. 按照队内提供的项目版本说明，从入口 main 与 launch 文件追踪 1 条数据流。
2. 画模块图，注明关键 topic、消息字段、坐标系与频率（未知请标未知）。
3. 运行 ROS2 demo talker/listener 或队内允许的离线节点。
4. 写下仍看不懂的 5 个代码位置与疑问。

## 基础必做（以可复现为准）

- [ ] 模块数据流图
- [ ] 关键源码路径索引
- [ ] ROS2 命令运行记录
- [ ] 未理解问题清单

## 选做挑战（不作为留队硬门槛）

- 在实际 rosbag 或离线输入中观察一条消息的时间戳

## 交付方式与证据

1. 在本人分支或个人提交目录中上传源码、CMakeLists、README 与测试记录；不要上传 `build/`、系统文件、未授权比赛视频、设备密钥。
2. 至少记录一次“错误现象 → 排查动作 → 最终结论”；即使未解决，也记录已验证的事实。
3. 提交一个 PR（初期不会 PR 可以先提交个人分支并报告链接），标题格式：`W11 学员昵称 - 任务主题`。
4. PR 描述复制 [提交模板](../../templates/SUBMISSION_TEMPLATE.md)，不得只上传截图而没有源码。

## 验收清单（主力抽查）

- [ ] 能说明 ROS2 Topic 与函数调用区别
- [ ] 区分测量结果与预测结果
- [ ] 图中未确认信息不会被当作事实

### 口头/录屏追问（任选 1～2 题）

1. 为什么多节点系统需要时间戳？
2. QoS 不匹配可能造成什么后果？

## 如果做不出来怎么办？

- 先完成能工作的最小版本，不要为了选做任务耗光 7 小时。
- 超过 30 分钟仍卡住，按 [求助模板](../../templates/HELP_TEMPLATE.md) 记录现象、尝试和日志，发 GitHub Issue / 群里求助。
- 截止前主动说明卡点可申请一次补交；**未完成但有真实排错记录**，与无说明不提交区别评价。
- 本周属于培训计划，不需要实车联调或新模型训练。
